# Manifest 文件追加与恢复

本步在纯内存 ManifestState/ManifestCodec 之上实现包内 ManifestFile。它只处理一份元信息文件，尚不验证 WAL/SSTable 引用，不初始化数据库目录，也不执行真正的日志轮换或后台刷盘。

## 接口与数据流

| 接口 | 行为 |
| --- | --- |
| create(path, initial) | 验证初始状态，以 CREATE_NEW 创建，完整写出 Header 与首状态并同步 |
| open(path) | 仅打开既有文件，验证全部完整历史，必要时修复残尾并同步 |
| current() | 返回最近成功提交或恢复选定的不可变状态 |
| append(next) | 验证相邻转换，完整追加并同步，之后才更新 current 与追加位置 |
| close() | 关闭资源；重复关闭安全，关闭报错后也不能恢复使用 |

文件创建使用 READ/WRITE/CREATE_NEW，恢复使用 READ/WRITE，不带 CREATE、TRUNCATE_EXISTING 或 APPEND。新建不能覆盖旧路径，恢复不能把缺失文件自动补成空文件。调用方必须独占该文件并串行使用；后续 LsmStore 会负责前后台的锁。

创建时先写 8 字节 Header，再写首个完整状态，最后 force(true)。只有同步成功才返回实例。失败时先关闭资源，关闭错误保留为 suppressed，原始错误优先；文件本身保留，不自动删除或重试初始化。它可能是残缺文件，也可能已有完整首状态，下一次 open 依据实际内容判断。

## 一次追加的成功边界

```text
验证 next 与 current 的转换，编码帧
    → 按 appendOffset 循环写完整帧
    → force(true)
    → 推进 appendOffset，替换 current
    → 返回成功
```

null 或非法转换在开始 I/O 前抛出参数异常，旧实例仍可继续。写入返回 0 或负数立即失败，不空转；实际短写按已写字节推进位置。追加前检查 long 文件位置不会溢出。

I/O 开始后发生 IOException、运行时异常或 Error，实例进入 FAILED，拒绝 append/current，仅允许 close。不能从当前缓存读取旧状态并误认为它仍代表磁盘文件集。

假设轮换帧已完整写出，但 force 报错：本次 append 不报告成功，内存状态也不切换；关闭后重新打开，若这条记录仍完整有效，恢复会采用它。失败不承诺回滚，因而后续数据库层不能在这种情况下擅自删除可能被引用的新旧文件。

## 恢复如何判断边界

先取得文件长度并验证完整 Header，再从偏移 8 开始扫描。每次只缓冲一个帧并保留最近状态，不收集全部历史。

1. 剩余不足 8 字节：视为残缺的最后帧前缀。
2. 前缀完整：复用 codec 的长度检查，要求范围合法且满足 36+8*N 的结构。
3. 长度合法但文件剩余字节不足：视为残缺载荷，不按该长度分配整个帧。
4. 字节完整：读取、检查 CRC、数量与字段；首条检查 requireInitial，后续检查 requireSuccessor。
5. 全部完整记录验证后，若存在残尾且已有有效状态，截断到最后有效边界并同步，然后返回可追加实例。

完整帧中的 CRC 或语义错误会报告记录起始偏移，不能跳过它寻找后面的合法状态，也不能静默使用旧状态。底层读取报错、无进展或与已取得文件长度不符的意外 EOF 也是错误，不会被当作可修复尾部。

需要注意长度判定的范围：如果损坏把长度改成合法的大值，使它超过剩余文件字节，这与真正未写完的载荷不能完全区分，会采用上述残尾规则。CRC 覆盖长度，但无法校验一个尚未完整读到的帧；此规则不承诺识别所有截断与损坏。

## 具体偏移示例

采用编解码笔记中的三种状态：

```text
Header    [0, 8)
初始状态  [8, 52)    revision=1，active=1
轮换状态  [52, 96)   revision=2，active=2，frozen=1
发布状态  [96, 148)  revision=3，active=2，sst=[3]
```

文件只剩 120 字节时，发布帧前缀完整，但 payload 不足，因此恢复 revision=2，截断到 96 并同步。之后重新追加发布状态从 96 开始，不能接在 120 后面。若发布帧 52 字节完整但 CRC 错误，则打开失败，文件保持原样。

若文件只有 Header，或者首状态尚未完整写出，则没有可以恢复的数据库状态：打开失败且不截尾、不重新初始化。零字节文件和残缺 Header 也拒绝。仅目录层以后才负责判断“已有空目录可以初始化”。

恢复验证全部历史的格式和转换，但不要求历史中已失效的文件还存在。最新状态引用的真实文件是否存在、冻结 WAL 是否等于封存长度，由下一步目录恢复负责。

## I/O 边界与生命周期

ManifestIo 只提供 size、按位置 read/write、truncate、force、close。默认代理 FileChannel，测试用真实 @TempDir 文件包一层故障代理；不复用 WAL 的包内接口，避免改变旧组件契约或提前设计通用文件框架。

状态为 OPEN、FAILED、CLOSED。工厂取得 I/O 所有权后，任何打开/初始化失败都尝试关闭，清理异常不覆盖主错误。close 在调用底层前先置 CLOSED，因此关闭报错也不会再次使用实例或重复释放。

此步不提供文件锁、目录项断电持久性或独立进程崩溃实验的保证；force 调用与结果不确定的边界通过注入验证。完整数据库的进程退出恢复仍需后续组合层验收。
