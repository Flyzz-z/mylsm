# 分阶段学习路线

以下为候选路线，每次开始一个阶段时再细化设计，不一次性生成全部实现。

| 阶段 | 学习与实现内容 | 你参与的关键步骤 | 验收重点 |
| --- | --- | --- | --- |
| 0：环境 | Java 21、Maven、JUnit、OpenSpec、Git | 理解目录与协作方式 | 构建与规范检查通过 |
| 1：内存 KV | 键值语义、比较规则、MemTable、删除标记 | 确定 API，完成 put/get/delete 与有序遍历 | 覆盖写入、覆盖、删除、边界和排序 |
| 2：WAL | 日志格式、写入顺序、校验与重放 | 设计记录编解码，实现恢复与尾部截断处理 | 重启恢复；区分正常关闭与崩溃持久性 |
| 3：SSTable | 不可变有序文件、块、索引 | 设计文件布局，实现读写与定位 | 往返一致、缺失键、边界和损坏输入 |
| 4：最小 LSM | MemTable 刷盘、多 SSTable 读取、文件集元数据 | 实现新旧版本选择、删除遮蔽与重启文件集恢复 | 跨层读写正确，旧值不复活 |
| 5：压缩 | 多路合并、压缩策略、文件替换 | 实现合并与 tombstone 回收条件 | 压缩前后语义一致，中断可恢复 |
| 6：查询与性能 | Bloom Filter、缓存、范围扫描、基准 | 解释取舍并选择一项优化实现 | 正确性不变，用测量解释收益与代价 |
| 7：进阶（可选） | 后台压缩、并发、快照/MVCC | 选择目标并定义一致性模型 | 并发与故障场景验证 |

初期优先建立单进程、单线程下可解释的正确性；具体键值类型、存储格式和持久性承诺在对应阶段共同确定。

## 每阶段的节奏

1. **理解**：画出读写路径，回答本阶段解决什么问题。
2. **设计**：创建 OpenSpec change，共同明确接口、不变量、非目标和验收场景。
3. **动手**：把核心任务拆成可独立练习的小步骤，你实现，助手提供渐进提示。
4. **验证**：运行针对性的测试，分析失败并修复。
5. **复盘**：你解释核心取舍，记录到 `docs/`；归档 change 并提交 Git。

下一阶段建议从“键值模型和 MemTable API”开始，先讨论如何表示缺失、删除与键的顺序，再写代码。
