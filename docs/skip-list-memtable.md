# 跳表 MemTable：节点、查找与写入

当前完成的是跳表的第一个实现小步骤：`SkipListMemTable` 的节点、多层查找、新键插入和已有键覆盖。类暂时保持包内可见；删除和快照尚未实现，因此还没有声明 `implements MemTable`。当前 `WalStore` 和 `LsmStore` 仍使用 `TreeMapMemTable`。

## 节点与层数

每个节点保存一个不可变 `ByteKey`、一个可以替换的 `Entry` 和一组前向指针 `next[]`。高度为 3 的节点拥有 `next[0]`、`next[1]`、`next[2]`，指向三层中各自的后继。不同层引用同一个节点，不复制键值。

`head` 是没有用户数据的头哨兵，预留 32 个指针。它的空 key 不参与比较，因此不会与合法的空字节键冲突。`height` 表示当前层数，初始为 1；`size` 统计不同 key 的数量，覆盖不会增加它。后续快照可以用这个数量预分配列表。

始终保持：每层的键严格递增；底层包含全部节点；高层节点同时出现在所有更低层。真实节点不保存 null key 或 null entry。

## 一次查找如何留下插入路径

例如插入 `17` 前，结构为：

```text
第 2 层：head ───────→ 12 ───────────────→ 25
第 1 层：head → 5 ───→ 12 ───────→ 20 ─→ 25
第 0 层：head → 2 → 5 → 9 → 12 → 18 → 20 → 25
```

`findPredecessor` 从最高层向右移动，但只越过严格小于目标的节点；遇到空指针或不小于目标的节点就下降。返回的是底层最后一个小于目标的节点，本例为 `12`。插入时还把每层的停留位置记入 `update[]`。

如果目标存在，它恰好是底层前驱的后继；如果后继为空或 key 不相等，就表示未找到。`get` 走同样的路径，但不创建 `update[]`。

向右后再下降不会越界：能够出现在某层的节点，必然拥有这一层及更低层的指针。

## 新键插入与旧键覆盖

如果找到相同内容的 key，直接替换节点的 `entry`，不用抽取新高度、修改前向指针或增加 `size`。原来的 `ByteKey` 可以保留，因为它不可变且与新 key 的内容相同。

如果没有找到，生成新节点高度。例如 `17` 高度为 2，则分别在第 0、1 层连接：

```text
node.next[level] = update[level].next[level]
update[level].next[level] = node
```

第 0 层变成 `12 → 17 → 18`，第 1 层变成 `12 → 17 → 20`；第 2 层不变。由于前驱小于 `17`，原后继大于 `17`，连接后仍然有序。若新节点高于当前层数，新增层的前驱就是 `head`。

参数、生成高度范围及节点分配均在修改表之前处理。错误输入不会发布半个节点。这个实现要求外部协调访问，不提供并发写入能力。

## 随机高度与确定性验证

默认从高度 1 开始，每次以 1/2 概率晋升，到 32 层停止。测试可通过包内 `IntSupplier` 构造入口指定高度，节点本身仍保持私有。这样可以稳定重现单层、混合层数和最高层插入，而不用等待随机事件发生。

正常随机分布及适当规模下，查找和写入的期望时间为 O(log n)，最坏为 O(n)。固定层数也不能为无限增长的规模保证对数性能。随机性影响效率，不影响数据语义。

本步测试覆盖各插入位置、命中与未命中、相等键覆盖、空键值、前缀与高位字节、null 拒绝和非法高度失败后的继续写入。固定种子的读写操作与 `TreeMapMemTable` 对照，确认不同结构保持相同查询结果，不用时间阈值判断性能。

本步验证通过：新增测试 16 个用例；`./mvnw test` 和 `./mvnw clean verify` 均运行 654 个用例，零失败、零错误、零跳过；`openspec validate --all --strict --no-interactive` 全部通过。
