## Context

本阶段开始时，阶段 4 已归档。LsmStore 前台串行调用，内部一个后台 flush 线程；有效 SSTable 按 Manifest 清单从旧到新排列。SsTableReader 只有点查和不可暂停的 scan，Writer 接受有序 Iterable。ManifestState 只允许日志轮换和冻结代发布。

动机见 proposal.md。用户讨论后已确认：单后台线程、自动阈值触发与同步手动调用、全部已发布表归并为一张、保留 Tombstone。按小步实现，不照搬 LevelDB 分层和 MVCC。

## Goals / Non-Goals

**Goals:**

- 分游标、多路归并、Manifest 转换和后台协调理解正确性边界。
- 保持 Value、Tombstone、缺失三态，支持进程退出恢复。
- 自动压缩期间前台仍可串行读写，锁外执行大量 I/O，后台至多一个执行任务。
- 记录缓冲随输入表数和块大小增长，不复制全库记录；已有索引另计。

**Non-Goals:**

- 见 proposal.md。不增加通用并发前台 API、范围迭代器、并行压缩或压缩中途抢占。

## Decisions

### 1. 自动触发与同步手动调用

实现状态：用户要求本轮直接完成自动阈值触发，后台归并、发布、回收及自动检测已接入；手动 compact() 仍是后续计划，不能将以下手动契约视为已实现。

自动条件为已发布 SSTable 数量达到阈值，默认 4、可配置且至少 2。成功恢复及发布文件集后重新判断，不主动冻结活跃表。输入为执行开始时全部已发布表，输出一张；0/1 张表无操作，因此不会对同一输出反复自动压缩。

计划中的手动 compact() 先复用 flush()，再在锁内登记请求对象并唤醒后台，通过 Condition 等待对象的 done/error；等待原子释放锁。前台仍串行，最多一个待处理手动请求。后台取走请求不等于完成；发布成功、无操作结束或失败时才登记结果并通知。已有自动任务可先结束，手动任务随后基于最新表集判断是否还需归并。

替代方案是调用线程执行、BlockingQueue 或独立线程池；选择复用现有线程和状态条件，减少任务队列、重复任务和多后台发布协调。同步只约束调用者等待。

### 2. 后台选择与生命周期

目标顺序为 frozen flush → 手动请求 → 自动压缩；本轮实现 frozen flush → 自动压缩，手动分支后续接入。没有任务则 await，不超时轮询。通知只是提示，共享状态代表工作，while 条件处理提前通知与虚假唤醒。

优先级只作用于任务边界。已开始压缩执行到底，期间前台可产生 frozen；唯一工作线程随后处理，冻结槽位忙且 active 已满时沿用背压。持续 flush 可能延后自动压缩，不引入公平调度或抢占。

等待中断保留标志并报告 InterruptedIOException，不取消已提交任务。后台 I/O、格式或提交失败进入 FAILED，记录原因并唤醒等待者；自动任务由后续读写和 close 报错。关闭后不接纳新请求或新自动任务，等待已开始任务安全结束，完成或明确终止尚未开始的手动请求，保留既有 frozen 恢复来源。

### 3. 三态与记录新旧

Manifest 清单位置越靠后，记录代际越新。相同键输出位置最大的输入记录，输出严格递增且唯一；文件编号不代表记录新旧。

get 对 Tombstone 返回 Optional.of(Tombstone)，对缺失返回 Optional.empty。丢弃标记会改变接口结果，所以首版保留最新 Tombstone，包含对从未存在键的删除。

### 4. 拉取游标与多路归并

SsTableReader.openCursor() 返回单线程 Cursor；next() throws IOException 推进，true 时 record() 返回当前位置的不可变记录，false 表示耗尽。创建不读取数据块；未推进、耗尽或关闭后 record() 拒绝调用。耗尽后的 next() 持续返回 false。耗尽仍占用 Reader，直到显式 close，避免提前推断最后记录已被消费。

每 Reader 至多一个游标，期间拒绝 get、scan 和另建游标；提前关闭清除记录/块缓冲并释放占用，不关闭 Reader。Reader 关闭时同时使游标失效，即使底层关闭报错也不能恢复使用；重复关闭安全。scan 回调不能重入创建游标。文件错误使 Reader 失效并清除游标记录缓冲，不把错误视为正常结束，失败后不能返回旧的当前记录。

游标保留当前已验证块，读取下一块前释放旧块引用；块完成 CRC、内容和索引边界验证后才产生记录。复用 readBlock，保持现有 scan/get 和文件格式，避免无关重构。

每输入提供一个头记录，最小堆选择下一键，排空相同键输入头，按 Manifest 位置选胜者并推进这些输入，然后输出。约 O(N log K) 时间、K 个输入块加堆与输出块的记录缓冲；Reader 索引另计。相比全表 TreeMap，不复制全库记录。

本步实现为 SsTableMerger.open(oldestToNewest)，提供 next/record/close。它借用 Reader 并管理自有游标，open 不预读数据块；第一次 next 初始化全部头。获取失败、推进失败或关闭时释放自有游标，不关闭输入 Reader。堆内头键不原地改变，必须先出堆再推进。同键组全部成功处理后才暴露胜者，失败后拒绝继续返回当前记录；具体流程及验证见 docs/sstable-merge.md。

Writer 的 Iterable 无 checked I/O：局部适配为 UncheckedIOException，在构建边界还原 IOException，保留 cause 和 suppressed 清理异常，不扩展通用文件框架。

### 5. 锁边界与 Manifest 转换

锁内固定输入、新旧顺序并分配新编号；锁外用独立 Reader/游标归并构建，前台继续使用现有 tables Reader，避免并发访问单线程 Reader。

唯一后台线程保证期间没有另一次 SSTable 发布，但前台可以轮换 WAL。提交时从最新 Manifest 构造后继，完整保留 active、frozen 及封存长度，仅把仍匹配的输入集替换为单张输出，revision 恰好加一。拒绝部分删除、空清单、任意重排及同时改变 WAL 的替换；原有轮换/flush 校验保留。

输出在开始时分配，可能小于随后新建的 WAL 编号，不能要求其大于提交前全部引用。压缩输出须大于全部输入 SST 编号且不与当前 WAL 重合；运行时分配器仍避开全部已分配编号和目录孤儿。合法历史中 SST 最大编号在 flush 发布和压缩替换时严格增加，轮换时不变，被回收 WAL 均由更大 SST 输出覆盖，因此已不在当前引用中的历史编号不超过 SST 上界；配合当前 WAL 查重拒绝历史引用编号复用。全体引用最大值仍不下降。本步已通过交错轮换、重复压缩与恢复历史验证此证明，见 docs/manifest-compaction.md。

沿用帧结构。旧程序不能识别压缩转换，不支持旧二进制回退打开已压缩数据库。

### 6. 发布与资源所有权

固定输入 → 分配编号 → 独立 Reader 流式构建并同步关闭输出 → 关闭独立输入 Reader → 打开输出并登记 owned → 锁内预构建读取集和最新 Manifest 状态 → 提交同步 → 安装读取集 → 关闭旧 Reader → 尝试删除旧 SST。

每个临时 Reader 在取得后即登记 owned，关闭成功才移除，失败保留最终释放路径；旧前台 Reader 在新集安装后再关闭。提交后安装只做引用赋值。前台 get 完整持锁且不泄露 Reader；安装时已有 get 已退出，后续 get 使用新集，所以首版不需要通用 Version 引用计数。压缩输入 Reader/游标及前台旧 Reader 均在回收文件前释放。

读取、构建、打开或提交失败时停止服务，保留恢复所需输入及提交结果不确定的输出，不承诺失败回滚。提交后资源关闭失败仍尝试释放其他资源、记录并报告失败，不能撤销有效状态；旧文件删除失败只留孤儿。清理异常不能掩盖主异常或遗失资源所有权。

### 7. 验收与退出窗口

| 退出边界 | 重启有效来源 |
| --- | --- |
| 部分或完整输出未发布 | 旧 SST 输入集及最新 WAL |
| Manifest 尾帧残缺 | 最后完整状态及其引用 |
| 新状态完整，旧输入未删或只删部分 | 新输出及最新 active/frozen WAL |

验收包括游标跨块/损坏、重复键、空键/值、二进制数据、删除后重写、手动等待、自动阈值、恢复检测、压缩期间前台读写与 WAL 轮换、flush 背压及关闭、故障注入和独立 JVM 退出恢复。清理先验证全部引用，再处理无引用内部普通文件，不动未知文件；不推导断电保证。

## Risks / Trade-offs

- [全量重写与临时空间] → 输入输出同时保留，接受首版较高写放大。
- [压缩延后 flush] → 不抢占，沿用有界冻结槽位和写入背压。
- [单输出索引超过既有 64 MiB 上限] → 明确失败，保留恢复来源，不拆表。
- [输入表多时块缓冲和索引成本增加] → 逐块读取，不宣称恒定内存。
- [期间 WAL 轮换] → 基于最新状态发布，单独验证编号与历史约束。
